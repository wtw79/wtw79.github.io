GitHub ↗

一个面向拍卖现场的竞价显示系统：标的管理、大屏投屏、实时竞价、成交归档，一站式完成"从开场到落槌"的全过程。

功能地图
📋
标的管理
新增/编辑/删除/设为当前，Excel 批量导入（原子替换、失败自动回滚），各标的独立配置。
🎛️
控制台
号牌输入即提交，增价/减价随时切换，起拍设置与投屏控制一屏完成。
🖥️
大屏展示
欢迎页 PDF/图片轮播，竞价页大字卡 + 实时报价表，欢迎页与竞价页可投不同副屏。
📦
成交归档
确认成交一键生成 Excel 报表、保存现场截图，按标的带时间戳归档，可查可溯。
📊
报表管理
全局与单标的两种模式，记录撤回/删除，导出 Excel 备查。
⚙️
系统设置
欢迎页/竞价页标题字体、表格结构、公式列配置，三主题全局即时切换。
🔢
数字软键盘
无物理键盘时的触屏报价方案，自定义布局，确认即报价。
🧮
公式计算列
参数列按公式自动求值（单位地价、楼面地价、溢价率），报价时实时计算。
🛡️
防错设计
撤回上一条应价、误删可精确还原、重新开始带快照、成交前双重校验。
🔒
本地数据留档
数据存于本机数据目录，不依赖网络，可整体备份迁移；单文件 exe 双击即用。
一场拍卖的完整流程
01 / 会前准备

把资料管起来

  • 标的管理中新增本场全部标的
  • 完善起拍价、竞价幅度、公告 PDF、图片
  • 系统设置确认大屏标题、表格结构与公式列
  • 连接副屏，预览欢迎页投屏效果
02 / 会中竞价

把报价亮出来

  • 设为当前标的，分别打开欢迎页与竞价页投屏
  • 展示资料、宣读拍卖文件
  • 录入号牌，输入即提交，大屏实时刷新领先
  • 随时调整幅度，落槌确认成交（或标记流拍）
03 / 会后收尾

把结果存下来

  • 核对成交记录
  • 按需导出 Excel 备查
  • 确认归档目录中的报表与截图
  • 继续下一标的，或结束本场拍卖

技术架构
🗄️
主进程权威态
多窗口下唯一数据源：控制台操作落库并广播，投屏窗订阅只读，崩溃重启后能立即回拉最新状态。
🪟
多窗口投屏
主控制窗 + 欢迎/竞价投屏窗，无边框全屏置顶，投屏窗崩溃自动重启，现场不会干等黑屏。
🔀
三宿主兼容
同一套前端代码可在 Electron / WebView2 / 纯浏览器三种环境运行，业务代码无需区分宿主。
💾
本地 SQLite
sql.js（WASM SQLite）持久化，增量 upsert + 僵尸清理，全部数据保存在本机数据目录。
⚡
公式引擎
Shunting-yard 后缀求值，支持 DD/C1-C4 变量，除零与语法错误安全返回，报价时实时计算。
📐
等比缩放渲染
大屏按 Viewbox Uniform 等比缩放，跨屏比例一致无黑边；大字卡超长数字自动缩放防溢出。

技术栈：Electron 33 · React 18 · Vite 5 · sql.js · xlsx · pdfjs-dist。electron-builder 打包为单文件便携 exe，自带 Chromium，无需安装 .NET / WebView2 运行时。

拍卖系统二次开发 · 2025 起

二次开发那套老系统

原系统是 2015 年的老东西，没 UI、没架构，像"计算机刚入世"。接手后一步步补全、理顺，做成了一套能用的入门级企业系统。真正要补的，不在有没有现成办法，而在这套东西此前从没被真正做透过，只停在表面。标的数据怎么建模、竞价怎么流转、成交怎么留痕、边界怎么兜，这些最琐细的活儿，没有现成可抄，只能一点点想清楚、做扎实。也才第一次，让我原本飘着的认知落成了实的东西。
